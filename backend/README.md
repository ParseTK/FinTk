# Virello API

FastAPI service that will own company data, caching, accounts and portfolios, so the web app never
holds a data-provider key. Python 3.13, managed with [uv](https://docs.astral.sh/uv/).

## Run it

```bash
cd backend
uv sync                                   # installs Python 3.13 and the locked dependencies
cp .env.example .env                      # optional; every setting has a safe default
uv run uvicorn app.main:app --reload --no-server-header
```

Then open <http://localhost:8000/docs> (interactive docs, off in production).

| Endpoint | Purpose |
|---|---|
| `GET /healthz` | Liveness: is the process up. Never touches dependencies. |
| `GET /readyz` | Readiness: runs the registered dependency checks, 503 with the failing names if one fails. |
| `GET /api/v1/meta` | Service name, version and environment. |
| `GET /api/v1/companies/search?q=` | Find companies by name or ticker (SEC directory). |
| `GET /api/v1/companies/{ticker}` | Company profile. |
| `GET /api/v1/companies/{ticker}/filings` | Recent SEC filings, optional `form` and `limit`. |
| `GET /api/v1/companies/{ticker}/financials` | Annual statements from SEC XBRL, `years` back. |
| `GET /api/v1/companies/{ticker}/prices/monthly` | Monthly closes. **Sample data** (labelled `source: sample`) until a price provider is added. |

Company data needs `VIRELLO_SEC_CONTACT_EMAIL`: SEC asks every client to identify itself. Without it
the company routes return 503 (and production refuses to start).

## Database and migrations

Postgres 17 through async SQLAlchemy and asyncpg. Alembic owns the schema; nothing creates tables
at startup.

```bash
uv run alembic upgrade head                              # apply every migration
uv run alembic revision --autogenerate -m "add thing"    # draft a migration from model changes
uv run alembic downgrade -1                              # undo the last one
uv run alembic upgrade head --sql                        # print the SQL instead of running it
```

Rules for migrations:

- **Read every autogenerated line.** Autogenerate is a draft: it cannot see renames or data moves.
- **Backward compatible.** The previous app version must keep working against the new schema, so
  add first and remove in a later release. A column rename is add, copy, switch, drop.
- **Reversible.** `downgrade()` undoes `upgrade()` exactly. Migrations time out on locks after 5 s
  instead of blocking live queries.
- A test fails if models and migrations disagree, or if two migrations share a parent (two heads).

How the database layer is built:

- `app/db/engine.py` builds the engine lazily (no connection until first use) with a **bounded pool**,
  `pool_pre_ping`, server-side `statement_timeout` and `idle_in_transaction_session_timeout`, and
  hidden bind parameters so values never reach logs.
- One short-lived session per request (`DbSession` dependency), committed on success and rolled
  back on any error. Routes that do not ask for a session never touch the database.
- Only repositories (`app/repositories`) contain SQL. Services and routes never see ORM objects.
- Database outages (connection, timeout, deadlock, exhausted pool) become a 503 in the standard
  error shape; constraint and syntax errors stay 500s because they are bugs. `/readyz` reports
  `database` when it is down.
- Price history is stored once per symbol and only the newest month is appended: the primary key
  `(symbol, month_end)` serves every read, writes are idempotent and batched.

Tests run against a real Postgres: set `VIRELLO_TEST_DATABASE_URL` (database name ending `_test`).
They skip locally without it and **fail in CI** without it.

## Sign-in

Social login only (Google and GitHub): there are no passwords to store, reset or leak.

- **Flow:** OAuth 2.0 authorization code with PKCE (S256). `GET /api/v1/auth/{provider}/login` sets a
  signed, ten-minute cookie holding the state and PKCE verifier; the callback checks the state in
  constant time, exchanges the code server to server, and starts a session. Failures redirect to
  `/sign-in?error=...`. The redirect after login is restricted to same-site paths.
- **Sessions:** a random 256-bit token in an `HttpOnly`, `SameSite=Lax` cookie (`Secure` and the
  `__Host-` prefix in production). Only its SHA-256 is stored, so a database leak cannot be replayed.
  Idle limit 30 days (sliding, rewritten at most hourly) and a hard limit of 90 days.
- **CSRF** on every state-changing request, in layers: the SameSite cookie, an `Origin` allowlist,
  and a per-session token sent as `X-CSRF-Token` (get it from `GET /api/v1/auth/session`).
- **Accounts:** a second provider links to the same user only through a *verified* email; an
  unverified or missing email is refused, which prevents the account-takeover-by-email trick.
  We store email, name and avatar URL, never provider tokens (nothing calls the provider after login).
- **Authorization** is separate from authentication: any endpoint taking an object id must call
  `require_owner` (or filter by user id). A foreign object answers 404, not 403, so ids cannot be probed.
- **Abuse:** login endpoints are rate limited per client. `DELETE /api/v1/me` removes the account and
  everything attached to it.

Register the OAuth apps (free, no card) and put the ids and secrets in `backend/.env`:

| Provider | Where | Callback URL |
|---|---|---|
| GitHub | Settings, Developer settings, OAuth Apps | `<VIRELLO_PUBLIC_URL>/api/v1/auth/github/callback` |
| Google | Cloud Console, APIs & Services, Credentials (OAuth client, Web application) | `<VIRELLO_PUBLIC_URL>/api/v1/auth/google/callback` |

GitHub allows one callback URL per app, so use a separate app per environment. Without credentials the
tests still cover the whole flow against a fake provider (`tests/fake_idp.py`).

## Watchlist and portfolio

Signed-in only. All amounts are US dollars, exact decimals, and travel as **strings** (never JSON
numbers: `0.1` as a float is not `0.1`).

| Endpoint | Purpose |
|---|---|
| `GET /api/v1/watchlist` | My watchlist, sorted, with company names. |
| `PUT /api/v1/watchlist/{symbol}` | Add (201 new, 200 if already there). |
| `DELETE /api/v1/watchlist/{symbol}` | Remove (204, also when it was not there). |
| `GET /api/v1/portfolio` | Holdings: one row per company, computed from its purchases, plus the total. |
| `GET /api/v1/portfolio/lots?symbol=` | My purchases. |
| `POST /api/v1/portfolio/lots` | Record a purchase (optional `Idempotency-Key` header). |
| `PUT /api/v1/portfolio/lots/{id}` | Replace a purchase (the company cannot change). |
| `DELETE /api/v1/portfolio/lots/{id}` | Delete a purchase. |

How it is kept correct and safe:

- **Average cost is computed, not typed:** a holding is the sum of its purchases. The database adds
  exactly (`NUMERIC`); the total is summed exactly and rounded to cents once, so rounded parts
  never drift.
- **Ownership on every id:** a purchase is only handed out after `require_owner`, and every
  statement also filters by `user_id`. Someone else's purchase and a missing one are the same 404.
- **Writes** need a session, the CSRF token and a trusted `Origin`, and are limited per person
  (`VIRELLO_WRITES_PER_MINUTE`). Request bodies reject unknown fields, floats and anything that
  would not fit the column.
- **Bounded storage:** 200 watchlist items and 500 purchases per person by default. The limits are
  checked under the person's row lock, so simultaneous requests cannot slip past them.
- **Safe to repeat:** adding or removing twice is a no-op, and a purchase created twice with the
  same `Idempotency-Key` returns the original (a different body with the same key is a 409).
- Symbols are checked against the SEC directory before they are saved.
- Lists are bounded by those caps, so they are returned whole rather than paged.

## Quality gates

CI runs exactly these, and so should you before opening a PR:

```bash
uv run ruff format --check
uv run ruff check
uv run pyright          # strict mode
uv run pytest
```

## How it is organised

```
app/
  main.py          application factory (create_app) and the app uvicorn serves
  core/            config, errors, logging, middleware, request context (no business logic)
  db/              engine and sessions, declarative base, ORM models
  auth/            sign-in primitives: tokens, PKCE, signed cookies, OAuth providers
  repositories/    the only code that writes SQL
  migrations/      Alembic revisions (one file per schema change)
  api/             routers: health at the root, everything else under /api/v1
  services/        use cases; depend on provider interfaces only
  providers/       data sources behind interfaces (base.py): SEC EDGAR, sample prices
  domain/          provider-independent models (money is Decimal)
  schemas/         API response models, kept apart from the domain
tests/             pytest, httpx AsyncClient; SEC calls are mocked with recorded fixtures
```

Conventions:

- **One error shape** for every failure: `{"error": {"code", "message", "request_id", "details?"}}`.
  Unexpected errors return a generic message and are logged with the request id, never leaked.
- **Request ids** on every response (`X-Request-ID`), accepted from the caller if plain and short.
- **Logs** are JSON, carry the request id, and never include bodies, headers, cookies or query strings.
- **CORS** is an explicit allowlist (`VIRELLO_CORS_ORIGINS`); `*` is rejected at startup.
- **API versioning:** `/api/v1` only changes additively; a rename or removal is a new version.
- **Configuration** comes from `VIRELLO_*` environment variables and is validated at startup.
